# Release notes 0.3.0

- **Веб-чат.** `chat-ui` запускается в отдельном контейнере с Nginx и доступен на `localhost:3000`. Ответы агента отображаются в Markdown, включая таблицы и блоки кода.
- **Продолжение диалогов.** API возвращает `session_id`. Повторный запрос с этим идентификатором загружает контекст из PostgreSQL. История сохраняется в транзакции до отправки ответа.
- **Рабочий каталог из конфигурации.** `default_workspace` в `config.yaml` задаёт рабочий каталог для новых диалогов. Каталог закрепляется за сессией. Поиск, чтение и запись используют этот каталог на протяжении диалога.
- **Файлы на хосте.** Compose монтирует `./tmp` в `/app/tmp`. При стандартном workspace `tmp` созданные файлы появляются в `tmp/<run_id>/` в репозитории.

## Обновление с 0.2.0

1. Сверь свой `config.yaml` с [примером](../src/main_agent/config/config.example.yaml). Проверь ключ OpenRouter в `.env`.
2. Запусти `mkdir -p tmp`, затем `docker compose up -d --build chat-ui`. Compose запустит также `app` и `postgres`. Если запускаешь API напрямую, укажи `DATABASE_URL`.
3. Открой [веб-чат](http://localhost:3000). Для клиентов HTTP API запрос без `session_id` создаёт новый диалог. Передавай возвращённый ID в следующих запросах.

Если в предыдущей сборке использовался именованный том `tmp_data`, его файлы нужно перенести в локальный `tmp` отдельно.
