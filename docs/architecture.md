# Thought Mate: базовая архитектура

## О проекте

Thought Mate — расширяемый AI-ассистент. Первым продуктовым сценарием станет
помощь в работе с кодом. В дальнейшем возможности ассистента можно будет
расширять новыми инструментами и интеграциями с LLM.

Архитектура строится вокруг предметной области агента. OpenRouter, файловая
система и другие внешние сервисы рассматриваются как инфраструктура и не
определяют модель ядра.

## Единый язык

- `Agent` — конфигурация поведения: инструкции, LLM и доступные tools.
- `Run` — выполнение одного пользовательского запроса.
- `Turn` — один ответ LLM внутри run.
- `Message` — элемент истории взаимодействия с LLM.
- `Tool` — операция, доступная агенту.
- `ToolCall` — запрос LLM на выполнение tool.
- `ToolResult` — результат выполнения tool.
- `ToolRegistry` — набор tools, доступных агенту.

Эти термины используются одинаково в документации, коде и тестах.

## Области системы

### Agent Runtime

`Agent Runtime` — ядро Thought Mate. Он описывает выполнение задачи агентом и
не зависит от конкретного LLM-провайдера или набора tools.

В него входят:

- `Agent`;
- `Run` и его состояние;
- история `Message`;
- `Turn`;
- `ToolCall` и `ToolResult`.

`Run` является корнем модели одного выполнения. Он хранит текущее состояние и
предоставляет операции для добавления сообщений, регистрации turns и
результатов tools, завершения или остановки выполнения.

На первом этапе run живёт в памяти. Механизм постоянного хранения будет
проектироваться только после появления соответствующего сценария.

### LLM Integration

Agent Runtime работает с LLM через внутренний контракт приблизительно такого
смысла:

```text
generate(history, available_tools) -> Turn
```

Контракт с LLM принадлежит application-слою Agent Runtime: именно agent loop
определяет, какие возможности ему нужны от модели.

Первая реализация контракта использует официальный Python SDK OpenRouter и
находится в инфраструктурном слое. Она отвечает за:

- преобразование внутренних сообщений и tools в формат OpenRouter;
- выполнение запроса;
- преобразование ответа OpenRouter во внутренний `Turn`.

Типы OpenRouter SDK не используются за пределами инфраструктурной интеграции.
Другой LLM-провайдер можно будет подключить новой реализацией того же контракта
без изменения Agent Runtime.

Конкретная реализация LLM передаётся в agent loop при сборке приложения в
`app.py`.

### Tools

Tools расширяют возможности агента и не входят в модель конкретного
LLM-провайдера.

Каждый tool определяет:

- имя и описание для LLM;
- Pydantic-схему аргументов;
- выполнение операции;
- результат или ошибку выполнения.

Pydantic-схема аргументов находится рядом с реализацией конкретного tool. Она
используется для генерации JSON Schema и проверки аргументов `ToolCall`.

`ToolRegistry` хранит доступные tools, предоставляет их описания Agent Runtime и
направляет `ToolCall` нужной реализации.

Coding tools станут первым набором возможностей. Их состав будет определён при
проектировании coding-сценария.

## AgentLoop

`AgentLoop` — application service, который выполняет один `Run`. Он связывает
доменную модель с LLM и tools, но не содержит реализацию OpenRouter или
конкретных операций.

Цикл выполнения:

1. Добавить пользовательский запрос в run.
2. Передать историю и доступные tools в LLM.
3. Сохранить полученный `Turn` в run.
4. Если turn содержит `ToolCall`, выполнить его через `ToolRegistry`.
5. Добавить `ToolResult` в run и снова обратиться к LLM.
6. Если turn содержит финальный ответ без новых tool calls, завершить run.

`AgentLoop` управляет последовательностью действий. `Run` управляет своим
состоянием и допустимыми изменениями.

## Модели и схемы

Доменные модели `Agent`, `Run`, `Message`, `Turn`, `ToolCall` и `ToolResult`
принадлежат Agent Runtime. Они описывают только необходимые ядру данные и не
копируют модели OpenRouter.

Pydantic может использоваться для доменных моделей, если его валидация и
сериализация полезны. Входная схема конкретного tool принадлежит самому tool и
не выносится в общий каталог схем.

## Начальная структура проекта

```text
src/main_agent/
├── agent/
│   ├── domain/
│   │   └── models.py
│   └── application/
│       ├── agent_loop.py
│       └── llm.py
├── infrastructure/
│   └── llm/
│       └── openrouter.py
├── tools/
│   ├── tool.py
│   ├── registry.py
│   └── coding/
├── config.py
└── app.py
```

- `agent/domain/models.py` содержит доменную модель Agent Runtime.
- `agent/application/agent_loop.py` содержит сценарий выполнения run.
- `agent/application/llm.py` содержит внутренний контракт с LLM.
- `infrastructure/llm/openrouter.py` реализует этот контракт через OpenRouter.
- `tools/tool.py` определяет контракт tool.
- `tools/registry.py` хранит и вызывает зарегистрированные tools.
- `tools/coding/` содержит coding tools и их Pydantic-схемы.
- `app.py` собирает application-слой с конкретными инфраструктурными
  реализациями.

Файлы и директории разделяются дальше только тогда, когда у существующего
модуля появляется несколько самостоятельных ответственностей.

## Развитие проекта

Новые возможности Thought Mate добавляются через:

- новые наборы tools;
- новые реализации LLM-контракта;
- развитие доменной модели Agent Runtime по мере появления новых сценариев.

Repositories, domain events, event sourcing и другие DDD-паттерны не вводятся
заранее. Они будут добавляться только при наличии задачи, которую действительно
решают.
