# Архитектура ThoughtMate2

ThoughtMate2 — CLI-ассистент для задач по программированию. Сейчас он принимает один запрос из командной строки, отправляет его в LLM через OpenRouter и выводит ответ в лог. Проект организован вокруг агентного цикла и интеграций. Отдельный доменный слой не предусмотрен.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `src/main_agent/app.py` | Точка входа CLI. Собирает запрос из аргументов, создаёт `AgentCore` и вызывает `invoke()`. |
| `src/main_agent/agent/agent_core.py` | Содержит агентный цикл `AgentCore` и класс `LLM`, который вызывает OpenRouter SDK. В `AgentCore` можно передать экземпляр `LLM`. |
| `src/main_agent/config/` | Pydantic-настройки и пример YAML-конфигурации. |
| `src/main_agent/prompts/base.py` | Системный промпт для задач по программированию. |
| `src/main_agent/agent/llm_contract.py`, `tool_contract.py` | Пустые модули для контрактов. |
| `src/main_agent/infrastructure/llm/openrouter.py` | Пустой модуль для интеграции с OpenRouter. |
| `src/main_agent/tools/` | Заготовки для инструментов и их реестра. |
| `src/main_agent/interfaces/` | Пакет без реализованных интерфейсов. CLI находится в `app.py`. |
| `infra/`, `docker-compose.yaml` | Сборка и запуск приложения в контейнере. |

## Агентный цикл

1. `AgentCore.invoke()` формирует историю из системного промпта и запроса пользователя.
2. `LLM.invoke()` отправляет историю в OpenRouter с пустым списком инструментов.
3. `AgentCore` берёт текст из первого варианта ответа и выводит его в лог.
4. Локальная переменная `tool_calls` пока всегда содержит пустой список, поэтому при положительном `agent_max_steps` выполнение завершается после первого успешного вызова LLM. Текст ответа выводится в лог, а `invoke()` возвращает `None`.

Системный промпт упоминает `bash`. В текущей реализации модель не может вызвать его или выполнить другие операции в рабочей папке.

## Подключение инструментов

Для работы с кодом можно начать с отдельных операций просмотра файлов, чтения и поиска по рабочей папке. При подключении инструментов реестр может предоставлять модели схемы доступных операций и направлять вызовы их обработчикам. Обработчики проверяют аргументы и доступ к файлам, в том числе границы рабочей папки после разрешения симлинков.

Цикл сможет продолжаться после вызова инструмента. Для этого `AgentCore` должен получить реальные `tool_calls` из ответа модели, добавить вызовы и их результаты в историю и снова обратиться к LLM. При штатном текстовом ответе без новых вызовов цикл завершается. `agent_max_steps` задаёт верхнюю границу числа обращений к модели за один запрос.
