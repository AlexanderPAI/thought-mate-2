# Thought Mate: базовая архитектура

## О проекте

Thought Mate — расширяемый AI-ассистент. Первым продуктовым сценарием станет
помощь в работе с кодом. В дальнейшем возможности ассистента можно будет
расширять новыми инструментами и интеграциями с LLM.

В основе проекта находятся три части:

- `AgentLoop` — управляет взаимодействием модели и инструментов;
- LLM-слой — предоставляет единый контракт для работы с моделями;
- tools — дают агенту доступ к возможностям приложения и окружения.

`AgentLoop` работает только с внутренним LLM-контрактом. Детали OpenRouter и
типы его SDK остаются внутри реализации этого контракта.

## AgentLoop

Один запуск цикла обрабатывает один запрос пользователя:

1. Передаёт LLM историю сообщений и описания доступных tools.
2. Получает ответ модели.
3. Если модель вернула текстовый ответ без новых tool calls, завершает запуск.
4. Если модель запросила tools, передаёт вызовы в `ToolRegistry`.
5. Добавляет результаты tools в историю и снова обращается к LLM.

Agent loop отвечает только за оркестрацию этого процесса. Он не содержит код
OpenRouter и реализацию конкретных инструментов.

## LLM-слой

LLM-слой отделяет agent loop от конкретного провайдера. Его контракт принимает:

- историю сообщений;
- описания доступных tools;
- параметры запроса к модели.

Результатом является нормализованный ответ ассистента, содержащий текст и/или
tool calls.

Первой реализацией контракта будет OpenRouter. Она использует официальный
Python SDK и отвечает за преобразование внутренних моделей в формат OpenRouter
и обратно.

Это позволяет в дальнейшем подключать другие LLM-провайдеры без изменения
agent loop.

## Tools

Каждый tool самостоятельно определяет:

- имя;
- описание для модели;
- Pydantic-схему аргументов;
- выполнение операции;
- формат результата или ошибки.

Pydantic-схема аргументов находится рядом с реализацией конкретного tool. Она
используется одновременно для генерации JSON Schema и валидации вызова модели.

`ToolRegistry` хранит доступные tools, формирует их описания для LLM и направляет
tool call нужной реализации.

Первый набор tools будет определён отдельно при проектировании coding-сценария.

## Внутренние модели

Agent loop, LLM-реализация и tools обмениваются собственными моделями:

- `Message` — сообщение в истории;
- `AssistantResponse` — нормализованный ответ LLM;
- `ToolCall` — запрос модели на вызов tool;
- `ToolResult` — результат выполнения tool.

Эти модели принадлежат ядру агента. Они не повторяют все типы OpenRouter, а
описывают только данные, необходимые agent loop.

## Начальная структура

```text
src/main_agent/
├── agent/
│   ├── loop.py
│   └── models.py
├── llm/
│   ├── base.py
│   └── openrouter.py
├── tools/
│   ├── base.py
│   └── registry.py
├── config.py
└── app.py
```

Конкретные tools добавляются в `tools/` вместе со своими Pydantic-схемами.
Дополнительные модули выделяются только после появления соответствующей
ответственности в коде.

## Развитие проекта

Новые возможности Thought Mate добавляются двумя основными способами:

- новые tools расширяют действия, доступные агенту;
- новые реализации LLM-контракта подключают других провайдеров и модели.

Основной agent loop при этом остаётся независимым от конкретного провайдера и
предметной области ассистента.
