# Архитектура ThoughtMate2

Один вызов CLI передаёт один пользовательский запрос в `AgentCore.invoke()`. Агент хранит историю сообщений в памяти этого запуска, обращается к OpenRouter и выполняет файловые операции локально.

## Компоненты

| Путь | Назначение |
| --- | --- |
| [`src/main_agent/app.py`](../src/main_agent/app.py) | Точка входа CLI. Настраивает логирование, собирает запрос из аргументов и вызывает агент. |
| [`src/main_agent/agent/agent_core.py`](../src/main_agent/agent/agent_core.py) | `AgentCore` управляет циклом и вызывает инструменты. Класс `LLM` отправляет сообщения через OpenRouter SDK. В `AgentCore` можно передать другой экземпляр `LLM` для тестирования. |
| [`src/main_agent/prompts/base.py`](../src/main_agent/prompts/base.py) | Системный промпт и схемы инструментов `LLM_TOOLS`, которые получает модель. |
| [`src/main_agent/tools/registry.py`](../src/main_agent/tools/registry.py) | `build_tools()` собирает реестр функций для запуска и привязывает каталог запуска к записи файлов. |
| [`src/main_agent/tools/files.py`](../src/main_agent/tools/files.py) | Проверка путей, чтение и запись UTF-8, рекурсивный поиск файлов по имени. |
| [`src/main_agent/config/`](../src/main_agent/config/) | Настройки Pydantic. Ключ провайдера загружается из окружения или `.env`, настройки агента — из `config.yaml`. |

## Агентный цикл

1. `AgentCore.invoke()` генерирует идентификатор запуска, собирает реестр и формирует начальную историю из системного промпта, списка имён рабочих каталогов и запроса пользователя.
2. `LLM.invoke()` отправляет историю и `LLM_TOOLS` в OpenRouter с `tool_choice="auto"`. Агент обрабатывает первый вариант ответа и логирует доступный текст.
3. Если модель вернула `tool_calls`, агент добавляет её сообщение в историю и последовательно выполняет вызовы по именам из реестра. Аргументы декодируются из JSON. Строковый результат передаётся как текст, список путей — как JSON. Ошибка инструмента, которую обработал агент, возвращается модели как строка `Error: …`.
4. Каждый результат добавляется в историю как сообщение с ролью `tool` и исходным `tool_call_id`. Следующее обращение к модели получает обновлённую историю. Цикл завершается, когда модель отвечает без вызовов инструментов или исчерпан `agent_max_steps`.

## Файловые инструменты

| Инструмент | Аргументы модели | Результат |
| --- | --- | --- |
| `find_files` | `workspace`, `pattern` | Отсортированные пути относительно workspace. Шаблон вроде `*.py` сопоставляется с именем файла. |
| `read_file` | `workspace`, `path` | Содержимое UTF-8 файла по пути относительно workspace. |
| `write_file` | `workspace`, `path`, `content` | Путь сохранённого UTF-8 файла относительно workspace, включая префикс `run-<id>/`. |

`workspace` — ключ в `workspaces`. Относительные пути в конфигурации отсчитываются от корня репозитория. Файловые функции отклоняют неизвестные имена workspace, абсолютные пути в вызовах и пути, которые после разрешения симлинков выходят за пределы разрешённого корня. Поиск пропускает файлы-симлинки и не спускается в каталоги по симлинкам.

Запись дополнительно ограничена подкаталогом `run-<id>/` выбранного workspace. Идентификатор общий для всех шагов одного `invoke()`. `write_file` создаёт нужные каталоги при записи. Возвращённый путь можно передать в `read_file` или повторно в `write_file` в рамках того же запуска. Чтение и поиск охватывают весь workspace.

## Контейнер

[`docker-compose.yaml`](../docker-compose.yaml) собирает сервис из [`infra/thougth-mate.dockerfile`](../infra/thougth-mate.dockerfile) и передаёт окружение из `.env`. Dockerfile копирует `src/main_agent` в образ и запускает Python от пользователя `appuser` в `/app`. Текущий Compose-файл не монтирует workspace. Для сохранения результатов на хосте между запусками контейнера нужно подключить том к каталогу workspace.
