# Release notes 0.4.0

- **Глобальная база знаний.** Добавлен Qdrant с постоянным томом `qdrant_data`. Одна опубликованная база доступна из всех диалогов.
- **Индексация Markdown.** `knowledge/documents.py` читает непустые UTF-8 конспекты и делит их по заголовкам и границам блоков. Фрагменты сохраняют источник, название документа, путь раздела и номер.
- **Предварительный просмотр.** `python -m src.main_agent.knowledge.index --dry-run` выводит нарезку и статистику.
- **Эмбеддинги через OpenRouter SDK.** Тексты с названиями документов и разделов отправляются пакетами. Проверяются соответствие индексов ответа и размерность векторов.
- **Хранение и публикация.** Векторы с текстами и метаданными записываются в Qdrant. Для имён коллекций и ID точек используется UUID4. После проверки количества точек алиас `knowledge` переключается на итоговую коллекцию.
- **Семантический поиск.** CLI `python -m src.main_agent.knowledge.search '<вопрос>'` выводит ближайшие фрагменты и источники. Документы и запросы кодируются моделью из `knowledge.embedding_model`.
- **Инструмент агента.** `tools/knowledge.py` предоставляет `search_knowledge(query)`, зарегистрированный в `tools/registry.py`. Агентный цикл поддерживает ожидание асинхронных результатов инструментов.
- **Приоритет конспектов по алгоритмам.** Системный промпт требует сначала обращаться к базе при вопросах об алгоритмах. При использовании базы агент должен сообщить об этом пользователю и указать источники.

## Обновление с 0.3.0

1. Добавь в `config.yaml` блок `knowledge` по [примеру README](../README.md#пример-configyaml). Обязательные поля — `qdrant_url`, `collection_alias`, `sources`, `embedding_model`, `top_k`. В текущем `config.example.yaml` поля модели эмбеддингов и размера выдачи расположены в `llm_config`; перенеси их в `knowledge`.
2. Для Compose укажи `qdrant_url: http://qdrant:6333` и `sources: [./knowledge]`. Каталог `./knowledge` монтируется в `/app/knowledge`.
3. Запусти сервисы и проверь нарезку.

```sh
mkdir -p tmp knowledge
docker compose up -d --build app chat-ui postgres qdrant
docker compose exec app /app/.venv/bin/python \
  -m src.main_agent.knowledge.index --dry-run
```

4. Выполни индексацию и пробный поиск.

```sh
docker compose exec app /app/.venv/bin/python \
  -m src.main_agent.knowledge.index
docker compose exec app /app/.venv/bin/python \
  -m src.main_agent.knowledge.search \
  'Почему поиск в отсортированном массиве быстрее?'
```

5. Задай вопрос об алгоритмах в чате и проверь вызов `search_knowledge` и упоминание базы знаний в ответе.

Индексация повторно вычисляет все эмбеддинги и расходует средства OpenRouter. Для локальных CLI-команд используй `uv run python -m ...`, запускай их из корня репозитория и укажи адрес Qdrant `http://127.0.0.1:6333`.

## Текущие ограничения

- Создание коллекции и загрузка в `write_collection()` находятся внутри цикла. При N фрагментах создаются N коллекций с нарастающим содержимым, последняя публикуется через алиас. Промежуточные и предыдущие коллекции автоматически не удаляются.
- Предел чанка в 4000 символов мягкий. Проверка токенного лимита модели отсутствует.
- В поиске пока отсутствует порог сходства. Качество выдачи нужно проверять на вопросах к своим конспектам.
- Метрики `AgentResponse` учитывают вызовы чат-модели. Токены и стоимость эмбеддингов инструмента поиска в них не включены.
